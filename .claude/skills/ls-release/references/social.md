# Announcement posts

Only when the maintainer asks for them. A release is finished without them.

Two drafts, kept outside the repo with the release body:

- **long** (LinkedIn): 6-10 short paragraphs. What changed, why it matters to someone running models on their own machine, one concrete number, no marketing voice.
- **short** (X, Bluesky, Mastodon): one hook line, three or four facts, the release URL last.

Rules:

1. Draft from the release body, not from the CHANGELOG.
2. Facts final, then an edit pass with whichever no-slop skill is installed, then the operator's writing style guide. The rewrite changes wording, so re-check the length budget afterwards.
3. X budget: 280 characters, a URL counts as 23, one emoji as 2. Count the final text.
4. No model or tool attribution, no emoji, unless asked for.
5. Posting is outward-facing. Draft, show both files, then post only on an explicit go-ahead, and diff the live post against the file afterwards. The posting tools themselves (browser composers, per-channel scripts) are part of the operator's environment, not this repo.
